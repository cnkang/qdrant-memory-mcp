# MCP 分发 0.2.6

MCP 分发 0.2.6 选择 Runtime 0.5.2。该版本使中断的远程写入可用同一 request 标识重放。
工具 Schema、传输层与授权规则不变。

## 变更

- 选择已发布的 Runtime 0.5.2 wheel 与 `v0.5.2` 标签修订。
- 随附 launcher 0.1.0-rc.7，携带 Runtime 0.5.2 载荷与依赖锁。
- 选择 DSH bundle 0.1.5。WorkBuddy 连接器继续使用 Skill 0.3.4。
- 远程写入失败时报告 `reason`、`retryable`、`replay` 与 `retry_after`。
  重放必须使用同一标识。`recovery_required` 表示 Owner 保留了请求，需要运维恢复。
- 更新接入指南、版本表与 CI 固定点。

## 安装

安装包前，请检查 PyPI 是否已提供 Runtime 0.5.2。

```sh
uvx --from 'qdrant-memory-mcp==0.2.6' qdrant-memory-mcp --help
```

共享 Owner 部署需在自己的环境中安装 Runtime：

```sh
python -m venv ~/.local/share/qdrant-owner-env
~/.local/share/qdrant-owner-env/bin/pip install \
  'hermes-plugin-qdrant-memory[local,mcp,remote]==0.5.2'
```

## 升级

替换分发版本并重启 MCP 客户端。Runtime 升级保持集合标识与账本，无需迁移步骤。

## 验证与限制

- 仓库测试套件针对固定的 Runtime 运行。
- Runtime 发布说明列出重启边界证据与未执行的检查。
- 托管安装使用 launcher 载荷。已预置旧版 Runtime 的主机在 launcher 重新预置之前
  继续使用该环境。
- PyPI 发布可用后，Registry 条目 `io.github.cnkang/qdrant-memory` 更新到 0.2.6。
