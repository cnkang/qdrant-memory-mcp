# MCP distribution 0.3.0

MCP 0.3.0 selects Runtime 0.6.0 for Codex memory portability. The Runtime remains
the only storage engine; the four scoped MCP tools and existing profiles retain
their interfaces. Verify the exact versions on PyPI and the MCP Registry before
using installation examples. Tags and public artifacts are immutable.

Codex v1/v2 import requires an authorized source preview and dry-run. Exports
provide bounded, checksummed JSON/Markdown, preserving readable data across
harnesses. Handoff remains HANDOFF_PENDING with native_verified=false until the
actual native client confirms adoption. No internal Codex database writes occur.

Managed launcher 0.1.0-rc.8 selects the Runtime release wheel and official
FastEmbed 0.9.1, retaining Pillow 13 and hash-pinned wheel-only installation.
WorkBuddy connector 0.2.5 and DSH bundle 0.1.6 select that launcher and refreshed
Skill 0.4.0. These npm/attachment publications have separate acceptance gates;
an MCP PyPI release alone does not prove their availability.

The FastEmbed 0.9.0-to-0.9.1 pipeline change requires explicit migration for
older managed CPU profiles. Their data/cache paths stay intact; do not relabel
them. Export with the old Runtime and, when authorized, re-embed into a new
profile and collection, verify, then switch clients. Retain the old launcher
and store for rollback. See the managed launcher upgrade guidance.

The Codex candidate stays at plugin 0.1.1 under Kang's plugins (`cnkang`).
Official Codex Marketplace submission remains paused. Protected cloud acceptance
uses the real Codex CLI with Ollama Cloud; GPT/ChatGPT account testing stays local.
Cloud CRUD, fixture import and handoff checks do not prove native adoption.

Upgrade into a new private environment and restart the MCP client. Preserve the
existing profile, collection, scope and embedding pipeline. Removing any client
integration must preserve memories, exports, model caches and original data.
