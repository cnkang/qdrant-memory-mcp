# MCP distribution 0.3.4

This release aligns the metadata-only MCP package with the published Runtime
0.7.0. MCP 0.3.3 pinned Runtime 0.6.2, so it could not resolve alongside the
current Runtime release.

The wheel stays metadata-only. The console entry point is still
`qdrant_memory.standalone:main`. The four stdio tools, their JSON Schemas, the
protocol name, scope and Owner authorization and the handshake are unchanged.
The persisted memory format is owned by the Runtime and does not change here.

## Maintenance stays operator-only

`upgrade plan`, `upgrade apply`, `upgrade resume` and `upgrade status` are
operator CLI routes. The MCP server never exposes them, never initializes a
collection on connect and never applies a policy on its own. Connecting a host
to an unplanned destination keeps the existing dense path and reports the
policy as legacy.

An MCP connection does not create payload indexes and does not change the
backend. Server and Cloud configuration, credentials and images remain the
operator's responsibility.

## Installation

Check [PyPI](https://pypi.org/project/qdrant-memory-mcp/0.3.4/) for
availability before installing:

```sh
uvx --from qdrant-memory-mcp==0.3.4 qdrant-memory-mcp --home /path/to/profile mcp
```

The distribution resolves `hermes-plugin-qdrant-memory[mcp]==0.7.0` from PyPI.
The MCP Registry entry is published separately after PyPI.

## Upgrade notes

An existing 0.3.3 host keeps the same profile and collection. The Runtime
0.7.0 operator commands add the policy record and the index reconciliation. No
host configuration changes are required. Run the Runtime `upgrade plan` and
`upgrade apply` once inside a maintenance window, then restart the host so it
reopens the destination with the accepted policy.

## Unchanged channels

The Codex plugin candidate, the Node launcher, WorkBuddy connector 0.2.6 and
the DSH bundle remain on their own published pins. Their availability is not
implied by this MCP release.
