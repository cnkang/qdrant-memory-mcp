# Qdrant Memory MCP 0.1.4

Python MCP 发行包现在精确依赖已公开发布的 Runtime 0.3.0。现有 CLI、四个
MCP 工具及 Python/uvx 安装方式保持兼容。Hermes 原生插件独立管理，现有用户
无需因其他宿主适配而升级。

Runtime 0.3.0 提供可显式选择的本地 CPU Embedding。托管启动器使用经过校验的公开
wheel 和完整锁定的依赖，托管宿主不再需要系统 Python、uv/uvx、Ollama 或 Qdrant
Server。启动器与各宿主 Connector 独立版本管理。启动器候选版 `0.1.0-rc.2` 为
Windows 增加了有界重命名重试：可执行文件被短暂占用（实时扫描，或探测进程中止后
的子进程句柄）时，准备过程不再直接失败。

WorkBuddy Connector 现在通过 WorkBuddy 托管 Node 运行时启动已发布的托管启动器：
固定精确的 npm 版本与 integrity，最低版本声明 5.0.0；Python/uvx 方式保留为文档化的
自定义 MCP 备选。纯配置 DSH Bundle（`@cnkang/qdrant-memory-dsh-bundle`）通过官方
`@deepseek-ai/dsh-mcp-client` 接入同一启动器，并保持显式准备步骤，使临时探测进程
不触发任何下载。

启动器升级时保留已有 Profile 的模型缓存配置；安装快照支持安全恢复，并拒绝
并发准备。MCP Bridge 会安全拒绝非法后端响应，不排队或自动重放记忆写入。
针对已发布的启动器 `0.1.0-rc.1`，精确的公开 `npx` 命令已在 Linux、macOS 和
Windows 上做端到端验证：连接超时预算内的冷握手、未准备探测进程保持干净、
后台准备、CRUD 与跨进程持久化。`0.1.0-rc.2` 的 pin 已于发布后复跑同一套验证并在三平台全部通过（2026-10-16）。

Connector 0.2.0 与 Bundle 0.1.0 已准备提交；真实桌面 Connector 安装、市场审核与
完整应用重启仍是独立的人工门禁。MCP 连接成功不代表后端准备完成。

```sh
uvx --from qdrant-memory-mcp==0.1.4 qdrant-memory-mcp mcp
```

请先按[快速开始](../quickstart.zh-CN.md)准备 Profile 和 Embedding Provider。
升级前备份数据，保留相同的 Profile、Scope 和 Embedding Pipeline。程序不执行
自动数据迁移。
