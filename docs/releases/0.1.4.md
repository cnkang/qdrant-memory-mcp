# Qdrant Memory MCP 0.1.4

The Python distribution now pins Runtime 0.3.0. Its CLI, four MCP tools and
Python/uvx installation commands remain compatible. Hermes users can continue
using their existing native installation independently.

Runtime 0.3.0 offers explicitly selected local CPU embeddings. The managed
launcher uses the verified public wheel and a complete dependency lock, so
managed hosts need no system Python, uv/uvx, Ollama or Qdrant Server.
Launcher and host Connector versions are managed separately. The launcher
release candidate `0.1.0-rc.2` adds bounded rename retries on Windows, so a
briefly locked executable (real-time scan or a terminating child after a
stopped probe) no longer fails preparation.

The WorkBuddy connector now starts the published managed launcher through
WorkBuddy's managed Node runtime. The connector pins the exact launcher version
and its npm integrity, declares WorkBuddy 5.0.0, and keeps the Python/uvx route
as a documented custom-MCP alternative. The configuration-only DSH Bundle
(`@cnkang/qdrant-memory-dsh-bundle`) installs the same launcher through the
official `@deepseek-ai/dsh-mcp-client`, with an explicit preparation step that
keeps the temporary probe download-free.

The launcher preserves existing profile cache settings across program upgrades,
recovers interrupted installation snapshots, and refuses concurrent setup.
The MCP bridge rejects malformed backend responses safely. It never queues or
automatically repeats memory writes. The exact public `npx` commands against
the published launcher `0.1.0-rc.1` are tested end to end on Linux, macOS and
Windows: cold handshake within the connector timeout, a clean unprepared
probe, background preparation, CRUD and fresh-process persistence. The
`0.1.0-rc.2` pin re-ran the same suite after its publication and passed on
Linux, macOS and Windows (2026-10-16).

Connector 0.2.0 and Bundle 0.1.0 are prepared for submission. Real desktop
Connector installation, marketplace review and full application restart remain
separate manual gates. A successful MCP handshake does not indicate backend
readiness.

Install the Python MCP with:

```sh
uvx --from qdrant-memory-mcp==0.1.4 qdrant-memory-mcp mcp
```

Prepare your profile and embedding provider using the [quickstart](../quickstart.md).
Back up data and keep the same profile, scope and embedding pipeline when
upgrading. No automatic data migration is performed.
