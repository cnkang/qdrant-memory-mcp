# MCP 分发 0.2.7

MCP 分发 0.2.7 固定使用已公开的 Runtime 0.5.3。Runtime 0.5.3 修复了
Qdrant Memory Provider 初始化失败后的生命周期处理，包括 WriterLease 冲突。
本 MCP 包仍是仅含元数据的分发包，业务实现由 Runtime 提供。

## 变更

- 固定依赖 `hermes-plugin-qdrant-memory[mcp]==0.5.3`。
- 将 MCP Registry 元数据和精确安装示例更新到 0.2.7。
- 四个 MCP 工具、工具 Schema、stdio 传输、Scope 规则和已存数据均不变。
  无需迁移，也不改变 Collection Schema。
- WorkBuddy/DSH 托管 Launcher 和 DSH Bundle 继续使用现有版本：它们运行 standalone MCP
  入口，不会创建 Hermes Native Provider，因此此生命周期修复不要求发布新的 npm 包。

## 升级

更新精确包版本并重启 MCP 客户端，以创建使用 Runtime 0.5.3 的环境。
现有 Profile 和记忆数据保留。Hermes Native Provider 用户应更新 Runtime 固定版本并
重启 Hermes/Gateway，以加载生命周期修复；竞争 Writer 退出后的恢复仍需显式执行，
没有后台重试循环。

```sh
uvx --from 'qdrant-memory-mcp==0.2.7' qdrant-memory-mcp --help
```

## 验证与限制

- 发布 workflow 在 PyPI 发布前，使用公开 Runtime 0.5.3 构建并测试 wheel 和 sdist。
- PyPI 发布后，在干净环境安装准确的 MCP 版本，检查 `tools/list`，并在隔离环境完成
  一次显式写入与读取。
- Runtime 0.5.3 的生命周期证据和未验证的环境范围记录在
  [Runtime 验收记录](https://github.com/cnkang/hermes-plugin-qdrant-memory/blob/main/docs/validation.md)。
- 只有在 PyPI 包公开且公开安装验收通过后，才将 Registry 条目
  `io.github.cnkang/qdrant-memory` 更新到 0.2.7。
