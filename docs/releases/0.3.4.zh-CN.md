# MCP 分发 0.3.4

本版把 metadata-only 的 MCP 包对齐到已发布的 Runtime 0.7.0。MCP 0.3.3 固定
Runtime 0.6.2，无法与当前 Runtime 版本共同解析。

wheel 仍是 metadata-only，控制台入口仍是 `qdrant_memory.standalone:main`。四个
stdio 工具、JSON Schema、协议名、scope 与 Owner 授权以及握手都未变化。持久化记忆
格式由 Runtime 负责，本版不改。

## 维护仍只在运维 CLI

`upgrade plan`、`upgrade apply`、`upgrade resume` 与 `upgrade status` 是运维
CLI 路由。MCP 服务不暴露这些路由，连接时不初始化集合，也不会自行 apply 策略。
宿主连接到未 plan 的 destination 时继续走既有 dense 路径，并显示为 legacy。

MCP 连接不创建 payload 索引，也不改后端。Server 与 Cloud 的配置、凭据和镜像仍由
运维负责。

## 安装

安装前先确认 [PyPI](https://pypi.org/project/qdrant-memory-mcp/0.3.4/) 已可见：

```sh
uvx --from qdrant-memory-mcp==0.3.4 qdrant-memory-mcp --home /path/to/profile mcp
```

本分发从 PyPI 解析 `hermes-plugin-qdrant-memory[mcp]==0.7.0`。MCP Registry 条目在
PyPI 之后单独发布。

## 升级说明

已有 0.3.3 宿主保持同一 profile 与集合。Runtime 0.7.0 的运维命令负责策略记录与索引
校准，宿主配置无需改动。在维护窗口内执行一次 Runtime 的 `upgrade plan` 与
`upgrade apply`，再重启宿主，让它以已验收的策略重新打开 destination。

## 未变化的渠道

Codex 插件候选、Node 启动器、WorkBuddy 连接器 0.2.6 与 DSH bundle 仍保持各自已发布的
pin。本次 MCP 发布不表示这些渠道已支持新组合。
