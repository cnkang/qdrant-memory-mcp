# MCP 分发 0.3.2

版本已从 tag `v0.3.2` 发布，源码 SHA 为
`587b6c16a70e29ed1ae322982a0c10a39834be17`。

- [PyPI 包](https://pypi.org/project/qdrant-memory-mcp/0.3.2/)
- [官方 MCP Registry 条目](https://registry.modelcontextprotocol.io/v0.1/servers/io.github.cnkang%2Fqdrant-memory/versions/0.3.2)
- [受保护的发布和公开安装工作流](https://github.com/cnkang/qdrant-memory-mcp/actions/runs/43267987034)
- Wheel SHA256：`783b34c2810d598050a9ed40fd88abfd460371db61371ddeeaa8fa15e2703131`
- Sdist SHA256：`d47ac5c60276029e77d4146f66827759704cd11972043bea1a6c4b02ee849eea`

MCP 分发 0.3.2 固定使用已发布的 Runtime 0.6.1 API。独立安装且显式启用的
Codex lifecycle 预览可调用 Runtime 的 `remote-event` 候选接口，而无需向 Owner 发送原始对话。
公开 Portable Codex 插件及其 Runtime 仍独立版本管理。

四个 stdio MCP 工具 schema、Qdrant schema 和已持久化的记忆格式均未改变。Owner 候选提交仍要求
操作者显式确认，并通过已授权的 Runtime grant。重试使用同一不可变 Owner event；FAILED 或
QUARANTINED 事件保持待处理状态，直到 Runtime 运维人员恢复。

发布工作流使用 MCP SDK 1.x 和 2.x 分别验收了 wheel 和 sdist；四次运行各有 635 项通过、1 项跳过。
跳过项用于解析文档中的 PowerShell 示例；Ubuntu 发布运行器未安装 PowerShell，因此不计作通过。
Exact-SHA 发布门禁以及 PyPI 和 Registry 公开安装验收均已通过。

GitHub Release 附有适用于 MCP 0.3.2 的 WorkBuddy connector 0.2.5 ZIP 及校验文件、
CycloneDX 1.6 SBOM 和许可证元数据汇总。Lifecycle 预览仍属实验功能：本版本未验收
Codex Desktop GUI hooks 或真实认证 Owner endpoint，也不符合公共插件目录的提交条件。
