# MCP 分发 0.3.6

MCP 0.3.6 是仅含元数据的 stdio 分发，固定依赖公开的 Runtime 0.7.2，并保持
四个作用域工具不变：

- `qdrant_memory_search`
- `qdrant_memory_add`
- `qdrant_memory_update`
- `qdrant_memory_delete`

Runtime 0.7.2 会在每个升级计划中记录本地 Ledger 的写水位。`upgrade apply` 与
`upgrade resume` 在持 profile writer lease 后再次比较该值；如果本 Runtime 在计划
创建后提交过写入，就拒绝该中断计划。拒绝时保留旧计划与恢复点，操作者可以先查看
阻断项，再显式执行 `upgrade plan --replace`。由不支持水位的旧版本保存的计划同样
需要这一步替换，即使其间没有任何本地写入。

## 安装

```sh
uvx --from qdrant-memory-mcp==0.3.6 qdrant-memory-mcp --home /path/to/profile mcp
```

该分发从 PyPI 解析 `hermes-plugin-qdrant-memory[mcp]==0.7.2`，不安装 Hermes，
也不通过 MCP 暴露任何 Runtime 维护命令。托管启动器、WorkBuddy 连接器与 DSH
bundle 各自选择 Runtime 版本，分别发布。已发布的启动器 `0.1.0-rc.12` 仍安装
Runtime 0.7.1。

## VS Code Copilot 验证

候选 wheel 在 macOS arm64 的 VS Code 1.146.0 桌面版通过验证，使用工作区
`.mcp.json` 和 PyPI 上的 Runtime 0.7.2。安装命令、profile 重启步骤和测试结果
见[快速开始](../quickstart.zh-CN.md#vs-code-copilot)。通过 PyPI 安装 MCP 0.3.6
的 Copilot 验证须等到发布后进行。

## 水位范围

水位只覆盖所选 profile 的本地 Ledger 中记录的写入。它不会观察使用另一份
Ledger 的其它 Runtime 进程、其它 profile 或设备，也不会观察其它客户端直接写入
Qdrant 的数据。需要稳定目的地的升级应先停止或隔离其它写入者，并取得服务商快照。
