# MCP distribution 0.2.6

MCP distribution 0.2.6 selects Runtime 0.5.2, which makes an interrupted remote
write replayable with the same request identifier. The tool schemas, the
transport and the authorization rules are unchanged.

## Changes

- Select the published Runtime 0.5.2 wheel and the `v0.5.2` tag revision.
- Ship launcher 0.1.0-rc.7 with the Runtime 0.5.2 payload and dependency lock.
- Select DSH bundle 0.1.5. The WorkBuddy connector keeps Skill 0.3.4.
- Report `reason`, `retryable`, `replay` and `retry_after` for a remote write
  failure. Replay the same identifier. A `recovery_required` reason means the
  Owner kept the request for operator recovery.
- Update the integration guides, the version tables and the CI pin.

## Install

Check that Runtime 0.5.2 is available on PyPI before installation.

```sh
uvx --from 'qdrant-memory-mcp==0.2.6' qdrant-memory-mcp --help
```

For the shared Owner deployment, install the Runtime in its own environment:

```sh
python -m venv ~/.local/share/qdrant-owner-env
~/.local/share/qdrant-owner-env/bin/pip install \
  'hermes-plugin-qdrant-memory[local,mcp,remote]==0.5.2'
```

## Upgrade

Replace the distribution pin and restart the MCP client. The Runtime upgrade
keeps the collection identity and the ledger. No migration step is required.

## Verification and limits

- The repository suite runs against the pinned Runtime.
- The Runtime release notes list the restart-boundary evidence and the checks
  that were not run.
- Managed installs use the launcher payload. A host that already provisioned an
  older Runtime keeps that environment until the launcher reprovisions it.
- The Registry entry `io.github.cnkang/qdrant-memory` is updated to 0.2.6 after
  the PyPI publication is available.
