# MCP 分发 0.3.0

MCP 0.3.0 固定使用 Runtime 0.6.0，提供 Codex 记忆可移植能力。Runtime 仍是唯一
存储引擎，四个带作用域的 MCP 工具及现有配置保持兼容。使用安装示例前先确认 PyPI
和 MCP Registry 的准确版本已公开；已发布 tag 和文件不可覆盖。

导入 Codex v1/v2 前须取得授权、预览源内容并执行 dry-run。导出提供有大小上限、
带校验和的 JSON/Markdown，保留跨 harness 可读数据。原生客户端确认采纳前，状态
保持 HANDOFF_PENDING、native_verified=false；不会写入 Codex 内部数据库。

托管 launcher 0.1.0-rc.8 使用 Runtime 正式 wheel、官方 FastEmbed 0.9.1 和
Pillow 13，保留哈希锁定及仅 wheel 安装。WorkBuddy connector 0.2.5、DSH bundle
0.1.6 使用新版 launcher 和 Skill 0.4.0。npm 与附件有独立发布和验收门禁；MCP
的 PyPI 发布本身不代表这些组件已经可用。

FastEmbed 0.9.0 到 0.9.1 的管线标识改变，旧托管 CPU profile 需要显式迁移。
旧数据和缓存路径保持不变，不得修改标记强行复用。先用旧 Runtime 导出，经授权
重新嵌入到新的 profile 和 collection，验证后再切换客户端；保留旧 launcher 和
存储以便回退。具体步骤见托管 launcher 的升级说明。

Codex 候选插件保持 0.1.1，Marketplace 为 Kang's plugins（`cnkang`），暂不正式
提交 Codex Marketplace。受保护的云端验收使用真实 Codex CLI 和 Ollama Cloud；
GPT/ChatGPT 订阅账号验收留在本地。云端 CRUD、导入和交接验证不等于原生采纳。

升级时创建新的私有环境，重启 MCP 客户端，保留现有配置、集合、作用域和嵌入管线。
移除任何客户端集成都必须保留记忆、导出、模型缓存和原始数据。
